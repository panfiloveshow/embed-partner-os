# Runbook: реестр и жизненный цикл контактов

## Назначение

Экран «Партнёры → Реестр» и API `/api/v1/contacts` реализуют PRT-005…007: хранят профиль контакта отдельно от организаций, показывают действующие роли contact–organization, обнаруживают совпадения рабочих каналов и сохраняют историю при архивировании или объединении.

## Чтение реестра

`GET /api/v1/contacts` поддерживает параметры:

- `search` — поиск по ФИО, email, телефону, мессенджеру и названию связанной организации;
- `status=active|archived|merged|all`; без параметра применяется `active`;
- `organizationId` — только действующая связь с указанной организацией;
- `duplicatesOnly=true` — только контакты с совпавшим email, телефоном или мессенджером.

Ответ содержит `total`, `truncated` и до 200 контактов. Для каждого контакта возвращаются профиль, `version`, статус жизненного цикла, активные связи с организациями и `duplicateMatches` с объяснением совпавших полей.

## Команды

Все мутации требуют заголовок `Idempotency-Key`. Повтор того же ключа и нормализованного тела возвращает сохранённый ответ, а другой payload с тем же ключом — `409 IDEMPOTENCY_KEY_REUSED`.

- создание: `POST /api/v1/organizations/:organizationId/contacts`;
- изменение профиля и одной связи: `PATCH /api/v1/contacts/:contactId`;
- мягкий архив: `POST /api/v1/contacts/:contactId/archive`;
- восстановление: `POST /api/v1/contacts/:contactId/restore`;
- объединение дубля: `POST /api/v1/contacts/:sourceContactId/merge`.

Изменение, архив и восстановление принимают актуальную `version`. При конкурентном изменении API отвечает `409 CONTACT_VERSION_CONFLICT` и передаёт `currentVersion`. Причина архива или восстановления обязательна. Объединённый контакт нельзя редактировать или восстанавливать; его каноническая запись задаётся `mergedIntoId`.

Пример архива:

```bash
curl -X POST http://127.0.0.1:3000/api/v1/contacts/CONTACT_ID/archive \
  -H 'Content-Type: application/json' \
  -H 'Idempotency-Key: 97a8dc58-21d7-4d17-adf6-cab0105b8c14' \
  -d '{"version":3,"reason":"Контакт покинул компанию"}'
```

## Транзакционные гарантии PostgreSQL

Изменение профиля/роли, увеличение `version`, AuditLog, OutboxEvent и завершение IdempotencyRecord входят в одну транзакцию. Архив хранится в `contact.archived_at`; запись не удаляется. Рабочие выборки «Сегодня», завершения задач, возможностей и импорта исключают архивные и объединённые контакты.

Перед включением PostgreSQL-режима применить expand-only миграцию:

```bash
npm run db:validate
npm run db:migrate
```

Миграция `20260818230000_contact_registry_lifecycle` добавляет `archived_at`, `version`, ограничение положительной версии и индекс жизненного цикла без удаления существующих данных.

## Проверка

```bash

```

Ручной smoke-сценарий: создать контакт, найти его в реестре, изменить профиль, убедиться в конфликте со старой версией, архивировать, проверить отсутствие в активном реестре и «Сегодня», затем восстановить. На ширине 390 px таблица должна перейти в карточки без горизонтального переполнения.
