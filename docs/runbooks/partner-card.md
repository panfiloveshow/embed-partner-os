# Runbook: реестр организаций и единая карточка партнёра

## Назначение

`GET /api/v1/partners` и экран «Партнёры → Реестр → Организации» реализуют PRT-003. `GET /api/v1/partners/:organizationId` агрегирует данные карточки PRT-004 без копирования фактов между сущностями. Модель `OrganizationGroup`, фильтр `groupId` и раздел состава группы в карточке покрывают PRT-002: каждый бренд или юридическое лицо остаётся отдельной организацией со своими доменами и операционными сущностями.

## Поиск и фильтры

Реестр принимает:

- `search` — название, юридическое наименование, тематика или действующий домен;
- `segment` — точная тематика;
- `ownerId` — ответственный;
- `stageCode` — текущая стадия возможности;
- `scoreMin` и `scoreMax` — диапазон Partner Score;
- `integrationStatus=not_started|planned|active|issue`;
- `activeAfter` — ISO-дата нижней границы последней активности.

Ответ содержит значения доступных фильтров, `total`, `truncated` и до 200 организаций. Состояние интеграции вычисляется из Placement: техническая проблема приоритетнее активного размещения, затем идут active, planned и not_started.

## Состав карточки

Карточка содержит девять вкладок:

1. «Обзор» — домены, юридическое наименование, резюме, текущая возможность, последнее взаимодействие, следующая задача и состояние размещений.
2. «Контакты» — действующие контакты и роли contact–organization.
3. «Возможности» — стадии, Score, владельцы и следующие действия.
4. «Взаимодействия» — хронология с контактом, автором, результатом и источником.
5. «Задачи» — сроки, статусы, владельцы и результаты.
6. «Размещения» — бизнес- и технический статус, последняя проверка и Alert.
7. «Метрики» — вычисляемые показатели с `dataAsOf` и признаком полноты.
8. «Документы» — массив документов; до подключения object storage корректно показывает пустое состояние.
9. «Аудит» — последние 200 событий организации и связанных Contact, Opportunity, Task и Placement.

Факты читаются из исходных таблиц. Например, стадия и Score остаются полями Opportunity, здоровье — Placement/HealthCheck, а история — append-only Interaction и AuditLog.

## Ограничения выдачи

Карточка доступна только в области проверенного actor: собственные/назначенные организации, команда либо все команды в зависимости от роли. CSV-экспорт использует ту же область и вынесен в отдельный permission-контур PRT-008, описанный в `partner-export.md`.

## Проверка

```bash
npm test
npm run typecheck
npm run build
```

Ручной smoke-сценарий: отфильтровать организации по S7, Score 70+ и planned, открыть все девять вкладок, перейти быстрым действием к Placement, переключиться между организациями и контактами. На 390 px карточка располагается перед списком, а страница не создаёт горизонтальное переполнение.
