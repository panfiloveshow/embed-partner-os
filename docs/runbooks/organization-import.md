# Импорт организаций CSV/XLSX

Реализация закрывает AC-07: до изменения реестра пользователь получает предпросмотр каждой строки, может отменить операцию, вручную разрешает неоднозначности и после применения видит построчный протокол.

## Формат файла

Поддерживаются `.csv` и `.xlsx` размером до 10 МБ и до 10 000 непустых строк данных. Для XLSX читается первый лист. CSV может использовать запятую или точку с запятой, поддерживает кавычки, переносы строк и удвоенные кавычки внутри значения.

Обязательные заголовки:

- `organization_name` — название организации;
- `domain` — публичный домен;
- `source` — источник записи.

Необязательные заголовки: `segment`, `owner_email`, `stage`, `contact_name`, `contact_role`, `contact_email`, `contact_phone`, `last_interaction_at`, `next_action`, `next_action_due_at`, `notes`. Пустая `stage` трактуется как `S0`. Неизвестные колонки игнорируются с предупреждением, а отсутствующие обязательные или повторяющиеся заголовки останавливают предпросмотр.

Минимальный CSV:

```csv
organization_name,domain,source,segment,stage
Пример Медиа,https://www.example.ru/news,conference-2026,Медиа,S0
```

Домен приводится к hostname в нижнем регистре без протокола, `www`, пути и завершающей точки. IP-адреса, localhost и значения без публичной доменной зоны не принимаются.

## Решения предпросмотра

- `create` — домен и нормализованное название не найдены;
- `update` — домен уже принадлежит организации, но название или непустой сегмент отличаются;
- `skip` — запись с тем же доменом не содержит изменений;
- `conflict` — строка невалидна, домен повторён внутри файла или такое название уже существует с другим доменом.

Для совпадения названия с другим доменом пользователь выбирает `create` или `skip`. Для невалидной строки и повторного домена допустим только `skip`, но выбор остаётся явным. Пока хотя бы один конфликт не разрешён, кнопка применения заблокирована.

## Пользовательский сценарий

1. Открыть раздел «Партнёры» и выбрать либо перетащить CSV/XLSX.
2. Проверить счётчики и сообщения по строкам.
3. Выбрать решение для каждой строки со статусом «Конфликт».
4. Нажать «Применить импорт» либо «Отменить импорт».
5. Сохранить итоговый экран как протокол: для применённых строк он содержит решение и ID сущности, для пропущенных — явный статус.

## API

- `POST /api/v1/imports/organizations/preview` — `multipart/form-data`, поле `file`;
- `POST /api/v1/imports/organizations/:jobId/commit` — JSON с массивом `resolutions`, обязательный `Idempotency-Key`;
- `POST /api/v1/imports/organizations/:jobId/cancel` — обязательный `Idempotency-Key`.

Пример команды применения:

```json
{
  "resolutions": [
    { "rowNo": 4, "decision": "create" },
    { "rowNo": 7, "decision": "skip" }
  ]
}
```

Ошибки возвращаются как `application/problem+json`. Для неразрешённых конфликтов `fieldErrors` использует ключи вида `rows.4`.

## PostgreSQL и повтор команд

Предпросмотр сохраняется как `ImportJob` и набор `ImportRow`. Применение выполняется в serializable-транзакции под advisory lock конкретного job. В одну границу входят изменения реестра, построчный протокол, AuditLog, OutboxEvent и завершение IdempotencyRecord. Повтор с тем же ключом и телом возвращает сохранённый ответ, а повтор ключа с другим телом отклоняется.

Создание строки может добавить Organization, нормализованный Domain, Opportunity, а при наличии данных — Contact, Interaction и следующую Task. Обновление изменяет только название и переданный непустой сегмент найденной Organization. Отмена переводит job в `cancelled` и не меняет реестр.

```bash
npm run db:validate

npm test
npm run build
```

Для интеграционной проверки PostgreSQL дополнительно выполнить миграции и seed, запустить приложение с `PERSISTENCE_MODE=postgres` и пройти оба пути: отмену предпросмотра и применение файла с конфликтом.
