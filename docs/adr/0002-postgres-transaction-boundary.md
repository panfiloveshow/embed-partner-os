# ADR-0002: транзакционная граница завершения задачи

- Статус: принято для R0
- Дата: 2026-08-17

## Решение

Команда завершения Task выполняет в одной PostgreSQL-транзакции:

1. Читает открытую Task и текущую версию Opportunity.
2. Завершает Task только при совпадении `version` и статуса `OPEN`.
3. Проверяет, что выбранный Contact имеет действующую связь с Organization задачи.
4. Создаёт неизменяемое типизированное Interaction с контактом, результатом и резюме.
5. Создаёт следующую Task, review-задачу для waiting либо оформляет close.
6. Обновляет Opportunity только при совпадении её версии.
7. При смене стадии добавляет неизменяемую запись StageHistory.
8. Добавляет AuditLog с before/after, включая созданное Interaction.
9. Добавляет OutboxEvent `task.completed` со ссылкой, контактом и типом Interaction.

Нулевое число обновлённых строк считается конфликтом параллельной записи и возвращает HTTP 409. Любая ошибка после первого изменения откатывает Task, Interaction, следующую Task, Opportunity, AuditLog и OutboxEvent вместе.

## Совместимость и rollout

Миграции являются expand-only: создают новые типы, таблицы, поля, ограничения и индексы без удаления или переименования существующих объектов. `interaction.contact_id` добавлен nullable, поэтому ранее сохранённые Interaction остаются совместимыми; новые ручные команды требуют контакт на уровне API. In-memory режим остаётся значением по умолчанию; PostgreSQL включается явно через `PERSISTENCE_MODE=postgres` после `migrate deploy` и seed.

## Ограничения

Bootstrap user используется только до интеграции корпоративного OIDC. Реальный PostgreSQL integration test не входит в локальный автоматический прогон, если Docker/PostgreSQL недоступен; транзакционная семантика в этом случае проверяется детерминированным store с rollback.
