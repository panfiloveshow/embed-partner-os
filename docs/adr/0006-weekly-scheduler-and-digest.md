# ADR-0006: планировщик недельного отчёта и доставка digest

- Статус: принято для R0
- Дата: 2026-08-18

## Контекст

ANL-006, событие `report.weekly_due` и AC-11 требуют автоматически создавать неизменяемый снимок и доставлять руководителю ссылку по понедельникам в 10:00 Europe/Moscow. Корпоративный почтовый провайдер и его API остаются открытым решением D-06, поэтому бизнес-логика не должна зависеть от конкретного SMTP или SaaS.

## Решение

Используются два независимых процесса:

1. `weekly-report-worker` вычисляет последний наступивший слот понедельника 10:00 MSK, формирует снимок за предыдущую завершённую неделю и использует детерминированный `Idempotency-Key`. Запуск после простоя выполняет catch-up того же слота, не создавая дубль.
2. `report-digest-worker` арендует только события `report.weekly.published` через существующий transactional outbox. События других типов остаются доступными своим consumers. Digest отправляется в согласуемый корпоративный HTTP notification gateway.

`OutboxEvent.id` передаётся как `Idempotency-Key` доставки. Ошибка HTTP или таймаут не подтверждают событие и включают существующий экспоненциальный retry. Снимок, аудит и outbox event по-прежнему фиксируются одной PostgreSQL-транзакцией.

Событие отчёта содержит ссылку, период, команду, число исключений и до семи решений/рисков. Внешнему gateway передаются только настроенные адресаты и управленческая выжимка; полный payload отчёта остаётся в защищённом хранилище приложения.

## Границы

- Worker без HTTP-сессии выполняется от системного actor; HTTP-генерация отчёта использует команду проверенного пользователя.
- Адрес gateway и получатели задаются окружением; реальные корпоративные credentials в репозиторий не входят.
- At-least-once на стороне outbox требует, чтобы notification gateway дедуплицировал запросы по `Idempotency-Key`.
- Реальные конкурентные PostgreSQL-проверки и интеграция с корпоративной почтой остаются обязательными перед pilot gate.
