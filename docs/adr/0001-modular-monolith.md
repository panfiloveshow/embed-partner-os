# ADR-0001: модульный монолит для R0

- Статус: принято для стартового среза
- Дата: 2026-08-17

## Контекст

ТЗ задаёт до 20 внутренних пользователей, 100 тысяч организаций, миллион взаимодействий и до 10 миллионов результатов проверок. Основная сложность находится в целостности бизнес-процесса, правах, фоновых заданиях и аудите, а не в независимом масштабировании десятков сервисов.

## Решение

Развивать один monorepo со следующими границами:

- `web` — React 19 + TypeScript + Vite;
- `core-api` — NestJS, REST `/api/v1`, OpenAPI 3.1-совместимый контракт;
- `domain` — чистые правила стадий, задач, SLA и приоритетов;
- `scheduler`, `general-worker`, `monitor-worker` — отдельные процессы после появления PostgreSQL и очереди;
- PostgreSQL — источник бизнес-состояния, RabbitMQ — транспорт at-least-once, object storage — крупные evidence и отчётные payload.

В первом срезе repository остаётся in-memory, чтобы проверить публичный API и главный пользовательский сценарий до фиксации корпоративной инфраструктуры. Контракты и доменные правила вынесены отдельно, чтобы замена repository не меняла поведение клиента.

## Инварианты следующего этапа

- команда и OutboxEvent фиксируются одной транзакцией;
- Task/Opportunity используют optimistic locking;
- StageHistory и AuditLog допускают только добавление;
- повтор одного Idempotency-Key с другим payload отклоняется;
- активная Opportunity имеет owner и следующую Task либо явное waiting/paused/closed состояние.

## Последствия

Положительные: быстрый старт, атомарные транзакции, единый контракт типов, простая локальная разработка. Ограничение: текущий in-memory repository нельзя использовать для пилота; PostgreSQL, миграции, SSO и аудит являются обязательным gate следующей версии.
