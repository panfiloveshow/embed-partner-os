# ADR-0005: неизменяемые недельные снимки отчёта

## Контекст

AC-11 и AC-21 требуют автоматически публиковать недельный отчёт, не менять его задним числом и воспроизводимо обрабатывать поздние данные. ANL-005 запрещает трактовать отсутствующие источники как нулевые значения, а BR-019 запрещает считать запуск только по стадии Opportunity без Placement и успешной проверки.

## Решение

`POST /api/v1/reports/weekly/snapshots` принимает понедельник отчётной недели, `dataAsOf` и `formulaVersion`. Доменный слой строит границы понедельник 00:00 — воскресенье 23:59:59.999 в `Europe/Moscow` и запрещает публикацию до окончания недели.

Для каждой команды и недели действуют две уникальности:

1. `(team, period, dataAsOf, formulaVersion)` возвращает уже опубликованный снимок без пересчёта.
2. `(team, period, revision)` выдаёт следующую ревизию при более позднем `dataAsOf` или новой версии формул.

Генерация сериализуется PostgreSQL advisory lock и выполняется в одной транзакции с IdempotencyRecord, AuditLog и OutboxEvent `report.weekly.published`. Таблица `report_snapshot` защищена от `UPDATE/DELETE` append-only триггером. Payload получает SHA-256 checksum; первая реализация хранит JSONB и `postgres://` URI, оставляя `payload_uri` стабильным швом для последующего переноса в корпоративное object storage.

Агрегатор строит результат, текущую воронку, возраст стадий, исполнение, исключения и 3–5 управленческих решений из Opportunity, StageHistory и Task. Метрики Placement, HealthCheck и истории переносов имеют `null` и `unavailable`, пока соответствующие источники не реализованы.

## Последствия

- Опубликованный отчёт расследуем и не меняется после появления поздних данных.
- Повтор одной команды и повтор генерации с новым ключом дают тот же снимок для одинакового среза.
- Поздние данные публикуются явной новой ревизией и не подменяют старую.
- Event `report.weekly.published` является швом для будущего планировщика и email digest.
- Синхронный endpoint сейчас служит командой для малых пилотных объёмов; тяжёлая асинхронная оркестрация и object storage подключаются без изменения read-контракта.
