# Changelog

Все заметные изменения проекта. Формат — Keep a Changelog; версии — SemVer.

## [1.1.1] — 2026-08-26

Починка фактора «Оценка охвата» в Радаре: трафик снова определяется и
учитывается в скоринге.

### Исправлено

- **Провайдер Tranco переведён на актуальный API**: tranco-list.eu убрал
  старый эндпоинт выгрузки списка целиком (`/api/lists/date/daily?limit=…`
  отвечает `400` для всех клиентов). Ранг домена теперь запрашивается через
  `GET /api/ranks/domain/{домен}` (свежий дневной список, лимит 1 запрос/сек
  — провайдер выдерживает интервал между запросами). Ранги и негативные
  ответы кэшируются на `RADAR_TRANKO_TTL_DAYS` дней (по умолчанию 7).
  Переменные `RADAR_TRANKO_COUNTRIES` и `RADAR_TRANKO_LIMIT` больше не нужны
  и удалены из `.env.example`.
- **Оценка трафика больше не теряется при мерже признаков**:
  `mergeRadarFeatures` брал только прежнее значение кандидата (при первой
  инспекции всегда пустое) и молча выбрасывал свежую оценку от провайдера —
  фактор «Оценка охвата» оставался 0/22 даже при работающем Tranco/Similarweb.
  Теперь сохранённая оценка не подменяется, а отсутствующая принимается из
  инспекции. Регрессионный тест зафиксировал поведение.

### Результат

Кандидат vc.ru при живой проверке: «Оценка охвата» 22/22 (Tranco:
3–20 млн визитов/мес), итоговый скор вырос с 50 до 75, приоритет medium → high.

## [1.1.0] — 2026-08-25

Углубление Радара: система сама находит ЛПР с подтверждённым ФИО и
должностью, регион площадки и Telegram-каналы — без платных источников.

### Добавлено

- **ЛПР из официальных данных ЕГРЮЛ (ФНС)**: найденный на сайте ИНН
  обогащается карточкой юрлица; руководитель («ГЕНЕРАЛЬНЫЙ ДИРЕКТОР: …»)
  становится первым в списке «ЛПР и целевые контакты» с confidence high и
  ссылкой на источник. **Поддержка ИП**: ФИО предпринимателя извлекается из
  названия записи («ИП Иванов Иван Иванович»). DaData используется только как
  резерв, если ЕГРЮЛ не дал директора.
- **Регион площадки из адреса регистрации ФНС**: поле адреса или короткое
  `rn` выписки нормализуется («Г.Москва» → «г. Москва», «СВЕРДЛОВСКАЯ ОБЛ» →
  «Свердловская область») и автоматически заполняет фактор «Целевая
  география» — до полного веса 8/8 без ручного ввода.
- **Telegram-каналы в «Каналах связи»**: ссылки t.me/telegram.me попадают в
  досье с пометкой, чей это канал — **«канал площадки»** (футер сайта) или
  **«канал автора»** (внутри статьи); служебные ссылки share/joinchat
  отфильтрованы. Кликабельны, открываются в новой вкладке.
- **Объём видеостраниц по карте сайта**: URL из sitemap.xml (включая
  sitemap-index) с признаками видео (`/video/`, `/watch/`, `/embed/`,
  `/translyacii/`, `.mp4`) поднимают верхнюю оценку фактора «Страницы с
  видео» — до 9–13 баллов без дополнительных HTTP-запросов; нижняя граница
  остаётся равной числу реально проверенных страниц.
- **Бесплатная оценка трафика Tranco** (`RADAR_TRANKO_ENABLED=1`): глобальный
  ранг домена переводится в полосу месячных визитов с честной пометкой
  «оценка по рангу»; Similarweb остаётся приоритетным при наличии ключа.

### Изменено

- География по тексту страницы распознаёт крупные города РФ как «Россия».
- Версия синхронизирована до 1.1.0 во всех пакетах монорепозитория;
  тестовый контур расширен до **335+ автотестов** (214 API, 69 веб,
  53 домен).

## [1.0.0] — 2026-08-25

Первый коммерческий релиз. Полный обязательный объём R0 по ТЗ (приёмка
2026-08-19, docs/acceptance-report-2026-08-19.md) плюс продуктовая доработка
для самостоятельного развёртывания у заказчика.

### Добавлено

- **Развёртывание одним стеком**: `Dockerfile.api` (multi-stage, рантайм без
  Prisma CLI, опциональный Chromium для L1 Радара), `Dockerfile.web` + nginx с
  прокси `/api`, `compose.prod.yaml` — PostgreSQL, автоматические миграции,
  API, веб и все воркеры; профиль `seed` для демо-данных.
- **Health-check** `GET /api/v1/health` без аутентификации (режим хранения,
  аптайм) — для Docker/K8s-проб и балансировщиков.
- **Встроенная аутентификация по паролю** (`AUTH_MODE_LOCAL_PASSWORD`):
  scrypt-хеши, HS256-сессии на 12 часов, rate-limit входа, идемпотентный
  бутстрап администратора (`LOCAL_ADMIN_*`), форма входа в вебе, выход;
  миграция `password_hash`. Для заказчиков без корпоративного SSO.
- **Радар**: обработка пользовательских проверок прямо в процессе API
  (`RADAR_INLINE_INSPECTION`, по умолчанию включено) — кандидат больше не
  зависает «в ожидании» без отдельного воркера; авто-проверка сразу после
  добавления кандидата; баннер о ненастроенном трафике
  (`SIMILARWEB_API_KEY`) вместо тихих нулей в Partner Score.
- **Уведомления через Telegram** (`*_CHANNEL=telegram`) для SLA-предупреждений
  и недельного дайджеста — без необходимости развёртывания внешнего шлюза;
  webhook-канал сохранён по умолчанию.
- **Доставка outbox-событий**: HTTP-транспорт с HMAC-подписью и
  Idempotency-Key (`HttpOutboxPublisher`) + непрерывный воркер
  `worker:outbox-relay`; сервис в prod-compose.
- **Эксплуатация**: скрипты `scripts/backup.sh` (pg_dump + ротация) и
  `scripts/restore.sh` (остановка приложения → restore → старт → health);
  runbook `docs/runbooks/deploy.md`; чек-лист безопасности
  `docs/security-checklist.md`.

### Изменено

- Хост прослушивания API вынесен в переменную `HOST` (ранее жёстко
  `127.0.0.1` — блокировало запуск в контейнере).
- Версия синхронизирована до 1.0.0 во всех пакетах монорепозитория.

### Известные ограничения

- 4 high-advisory в цепочке Prisma CLI (dev-инструмент, отсутствует в
  runtime-образе) — см. docs/dependency-audit.md.
- RabbitMQ-publisher для outbox остаётся за корпоративной конфигурацией
  брокера; базовая доставка реализована HTTP-транспортом.
- TLS-терминация выполняется инфраструктурой хостинга.

## [0.1.0] — 2026-08-19

Первый вертикальный срез по ТЗ v1.0: экраны «Сегодня», «Воронка», «Отчёты»,
реестры контактов/организаций, импорт CSV/XLSX, Радар, Placement+L0, SLA и
